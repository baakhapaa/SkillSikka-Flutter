# 2026-09-18 — SkillSikka Flutter

## Unified the button/chip tap feedback across the app

**Problem reported:** the `View` button on Premium Courses had a weak, barely-visible
press effect. Wanted it to match the Class 6–10 chips on the Courses page, which
already felt right.

**Root cause:** two hand-rolled copies of the same "soft raised" recipe had drifted.
- `courses.dart` `_chip()` — rich: shadow travel 3px→1px, inset gradient flips
  direction on press, specular highlight dropped on press, plus hover scale 1.06
  and slide -6% applied by the parent `_buildChips`.
- `premium_courses_page.dart` `_ViewButton` — weak: only the shadow offset changed
  on press, and the hover alpha nudged. No scale, no slide, no inset flip, no
  highlight drop. So the press was nearly invisible.

**Fix:** extracted one shared widget, `lib/core/widgets/pressable_chip.dart`
(`PressableChip`), holding the full recipe, and pointed all three call sites at it:
- `courses.dart` Class 6–10 chips
- `premium_courses_page.dart` `View` button (fontSize 10 / w700 / pad 12×7)
- `premium_courses_page.dart` top category chips (All, Art & Craft, Design, …)

Deleted the now-dead `_chip()` method, `_ViewButton` + `_ViewButtonState`, and the
`_hoveredChip` / `hoveredCategory` state fields (hover tracking now lives inside
`PressableChip`).

**Bonus behaviour change:** `PressableChip` unifies `selected` (persistent
pushed-in state, for single-select chip rows) with a real finger-down `_pressed`
state into one `_depressed` getter. The Courses chips previously had *no*
finger-down feedback at all — they only reacted once `selected` flipped. They now
press in while held, same as the View button.

**Verified:** `flutter analyze` → "No issues found!". Added
`test/pressable_chip_test.dart` covering rest offset, press travel, highlight drop,
hover scale, selected persistence, and onTap firing — but see the environment note
below, these could not be executed here.

## Environment gotcha: `flutter test` is unusable on this machine

Two separate blockers, in order:
1. `%PROGRAMFILES(X86)% environment variable not found.` — the toolchain's cmd
   wrapper can't resolve it. Workaround: inject `ProgramFiles(x86)` into the child
   process env from Python (bash can't export a name with parentheses).
2. After that, tests compile but die with
   `Unable to connect to flutter_tester process: WebSocketException: Invalid WebSocket upgrade request`.
   This happens **outside** the sandbox too, and the pre-existing
   `test/navigation_test.dart` fails identically — so it is environmental, not
   caused by any code change.

`flutter analyze` and `dart format` both work fine. Don't burn time trying to make
`flutter test` run; use `flutter analyze` plus manual verification on a device.

## ICT & AI Bootcamp: duration selector now drives the carousel

**Problem reported:** selecting 4 / 7 Days in the bootcamp dropdown didn't change
which card was shown. The user also flagged that the dropdown items reordered
themselves (the selected value jumped to the top) — they'd put the "bring the
selection to the front" logic in the wrong place.

**Fix in `_buildIctBootcamp` (home_page.dart):**
- `_bootcampCamps` is now duration-tagged:
  `(4, ict1.png, 'Sundarbazar')` and `(7, ict2.png, 'PALUNGTAR')`.
  Per the user: ict1.png is the 4-day artwork, ict2.png the 7-day one.
  (Both are the same poster — "Empowering the innovation of tomorrow" — over
  different backgrounds: night/globe vs Himalaya/flag.)
- Dropdown order is now a fixed `_bootcampDurations = [4, 7]`. The old
  `[_selectedBootcampDays, ...the rest]` reorder is gone.
- The **carousel** is what reorders:
  `[...camps.where(== selected), ...camps.where(!= selected)]`.
- Added `_bootcampController` so the list animates back to offset 0 on change.
  Needed because a card is 311px wide on a ~390px screen — if the user had
  scrolled to card 2, reordering alone wouldn't reveal the new first card.
- Added `ValueKey(camp.$2)` on each item so reordering stays stable.
- Record field indices shifted: `$1` = duration, `$2` = asset, `$3` = label.

**Verified:** `flutter analyze` clean. Also ran the reorder expression as a plain
Dart script (works — `dart run` doesn't need `flutter_tester`):
4 Days → ict1 → ict2, 7 Days → ict2 → ict1, no cards lost, stable on toggle.

## Related finding: `_glossyGlassButton` is the original of the PressableChip recipe

`home_page.dart` (~line 846) already had `_glossyGlassButton` — identical
shadow/blur/offset/alpha numbers to the recipe I extracted into
`lib/core/widgets/pressable_chip.dart` earlier today. So `courses.dart`'s `_chip`
was a copy of *it*, not the other way round.

The codebase now has **five** implementations of the same soft-raised surface:
`PressableChip` (new), `_glossyGlassButton` + `_classFilterChip` (home_page),
`instructor_page.dart`'s own chip, and `recommended_course.dart`'s `_glassChip`.
`_glossyGlassButton` is more general (takes `child`, `fill`, `pressed`/`hovered`
from the parent) while `PressableChip` owns its own hover/press state and a text
label. Consolidating these is a real follow-up, not done yet.
